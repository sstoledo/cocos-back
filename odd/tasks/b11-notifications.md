# B11 — Notifications Backend (cocos-back)

## Objective
Greenfield notifications module: per-user notifications generated by business events (WO ready, PO received), readable by all authenticated roles.

## Problem / Why
The frontend has a notifications page stub and ReadOnly role sees only dashboard+notifications — notifications are a first-class MVP surface. Today zero notification infrastructure exists (no model, no module, no event bus).

## Scope (authorized)
- IN: Notification Prisma model + migration, notifications module (list own + mark read + mark all read), generation triggers in work-orders.service (status→ready) and purchase-orders.service (receive, partial + full), unit + e2e tests.
- OUT: low-stock alerts (no minStock field — bigger scope), real-time (SSE/WS), cancel notifications, @nestjs/event-emitter dependency (direct service calls instead), frontend UI (F11).

## Binding decisions (maintainer)
- Events: **WO ready + PO received (partial and full)** only.
- Delivery model: one Notification row PER USER in target roles (per-user read state).
- Recipients: WO ready → Admin + Reception. PO received → Admin + Purchasing + Warehouse.
- Generation: direct service-to-service calls (no event bus — repo has none, no new deps).
- Read: ALL authenticated roles read their own notifications.
- No real-time — frontend will poll via React Query (F11).

## Contract (defined here — frontend is a stub)
- `GET /notifications?unread=true&page=1&limit=20` → `{ data: Notification[], meta: { page, limit, total } }` — own notifications, newest first
- `PATCH /notifications/:id/read` → 200 updated / 404 NOTIFICATION_NOT_FOUND (own only — never 403, don't leak existence)
- `PATCH /notifications/read-all` → 200 { count }
- Notification: { id, type ('work_order_ready'|'purchase_order_received'), title, body, link, readAt: string|null, createdAt }
- Links: `/work-orders/:id`, `/purchase-orders/:id` (frontend routes exist)
- WO title: `Orden de trabajo {orderNumber} lista`; PO title: `Orden de compra {purchaseOrderNumber} recibida` (+ "parcialmente" when partial)
